# 规则契约（M1）

> 冻结日期：2026-10-16（M5 章节补充于 2026-10-17）
> 适用范围：`field-command-main` 当前版本（原创陆战与海空军、可开关战争迷雾、2–4 人）
> 每条规则都由 `test/contract.test.mjs` 或 `test/invariants.test.mjs` 锁定；改动实现会让对应测试失败，必须同步更新本文。

## 一、规则集与状态

### 1.1 状态字段

| 字段 | 含义 | 取值 |
| :--- | :--- | :--- |
| `version` | 状态结构版本 | 固定 `1`，不兼容时 `validateState` 抛错 |
| `fog` | 战争迷雾开关 | 布尔值，开局确定后不再改变；见第十章 |
| `mapId` / `width` / `height` | 地图身份与尺寸 | 必须与 `MAPS` 一致 |
| `tiles[]` | 地形与建筑层 | 长度 = `width × height`，按行优先索引 `y * width + x` |
| `units[]` | 单位表 | 每个棋盘位置最多一个单位 |
| `players[]` | 席位 | `id` 0–3 唯一，`team` 0–3，含 `funds` / `energy` / `power` / `defeated` |
| `currentPlayer` | 当前行动席位 | 必须是未战败的席位 |
| `day` / `turn` | 天数与回合序号 | 均为 ≥ 1 的安全整数 |
| `phase` | 对局阶段 | `playing` 或 `finished` |
| `winner` | 胜利队伍 | 进行中为 `null`；结束时为存活队伍的 `team` |
| `log` | 事件文本 | 最多保留最近 70 条 |

房间另有一个不属于规则状态的字段：`requestLog`（请求去重记录，上限 64 条）。它由会话层维护、随存档持久化，但**不进入任何客户端可见的快照**。

**规则版本**：首版只有一种规则集，不携带独立的 `rulesetVersion` 字段。若将来引入多套规则，必须新增该字段并提供存档迁移或明确拒绝。

**存档版本**：`save-store.mjs` 的 `SAVE_VERSION` 为 `3`，高于规则状态的 `version`（`1`）。两者独立：前者描述文件外壳，后者描述战局结构。版本 1 的存档文件在载入时补上空 `requestLog` 并默认无迷雾；版本 2 补上 `fog: false`。缺少迁移器或版本高于当前构建都会导致载入失败，而不是被静默接受。

### 1.2 回合结构

- 回合顺序按 `players[]` 数组顺序循环，跳过已战败席位。
- 轮次索引回绕时 `day` 加 1。
- 每回合开始时：清除该席位的能力状态、发放收入、重置本单位 `acted`、结算据点维修与补给。
- 进入回合时结算而非结束时结算维修，因此「回到本方回合」与「能力结束」是同一时刻。

### 1.3 必须成立的状态不变量

任何 `applyAction` 之后的状态都必须满足：

1. 棋盘上不存在两个同位置单位。
2. 单位 `hp ∈ [1, 10]`，`fuel ∈ [0, maxFuel]`，`ammo` 为 `null` 或 `[0, maxAmmo]`。
3. 玩家 `funds ≥ 0`，`energy ∈ [0, 100]`。
4. 存活玩家（`!defeated`）必须仍有至少一支部队或一座工厂。
5. 已战败玩家不得持有单位、建筑或能力状态。
6. 能力状态与能量一致：`power === "power"` 时 `energy ≤ 50`，`power === "super"` 时 `energy === 0`。
7. 占领进度非满时，必须在对应格上站着进度归属方的可占领单位。
8. `phase === "playing"` 时至少有两支队伍存活；`finished` 时恰好一支。
9. `fog` 必须是布尔值；`log` 的每条目要么是字符串，要么是带合法 `seat` 的 `{ seat, message }`（迷雾私有条目，见 10.2）。

第 4、5、6 条由 M1 新增，第 9 条由 M4 新增，之前的校验器不检查。

### 1.4 确定性

规则核不读取时间、网络或未受控随机源（`engine.mjs` 中无 `Math.random`、`Date.now`）。相同状态与相同指令必然得到相同结果，已由测试断言锁定。这一性质服务于存档恢复、AI 推演与联机重放，**不代表客户端需要自行模拟来达成共识** —— 主线是房主权威模式。

## 三、移动

- 移动范围按地形消耗的加权重计算，上限为 `min(移动力 + CO 加成, 当前燃料)`。
- **燃料按path消耗扣除，不是按格数**。例如森林对轮胎消耗 3、对履带消耗 2。
- 友军（含队友）所在格**可以穿行但不可停留**；敌军所在格是硬阻挡。
- 玩家手绘路径逐格校验邻接、地形、敌友阻挡与燃料，不能只检查终点可达性。
- 移动力为 0 的单位仍可执行原地「待机」。
- `reachable(state, unitId)` 返回可达格列表（含路径与消耗），**不判断该单位是否已行动**；是否允许行动由 `applyAction` 决定。客户端以 `acted` 过滤。

来源与消耗必须取自 `reachable` 返回的 `cost`，不要在前端重算。

## 四、战斗

### 4.1 伤害公式

内部与显示生命统一使用 1–10 的可视 HP（本实现没有 1–100 的内部 HP 层）：

$$
D = \min\left(H_d,\ \max\left(1,\ \operatorname{round}\left(B \times \frac{H_a}{100} \times A \times \frac{1 - \frac{s\,H_d}{100}}{F}\right)\right)\right)
$$

| 符号 | 含义 |
| :--- | :--- |
| $B$ | 武器对目标兵种的基础伤害（百分数，如 75 表示 75%） |
| $H_a$ | 攻击方当前可视 HP（1–10） |
| $H_d$ | 防御方当前可视 HP（1–10） |
| $A$ | 攻击方 CO 系数，基准 1 |
| $F$ | 防御方 CO 系数，基准 1 |
| $s$ | 目标格地形防御星数 |

要点：

- **没有随机数**。同类攻击在同一状态下结果完全相同。
- 地形保护随防御方 HP 递减：`1 − s·H_d/100`。满血站在 4★ 总部上减伤 40%，残血时保护接近消失。
- 取整在最后一步，使用 `Math.round`；下限 1，上限为目标剩余 HP。
- 因为步进取整，公式中 `B` 直接参与乘法，不要先除以 10 再乘 HP 比例；早期版本曾按不同的中间步骤推导出错误常数。

### 4.2 结算顺序

`applyAction` 在移动类指令中按以下顺序执行（攻击类指令的合法性已在之前全部校验，因此移动结算不会中途失败）：

1. 移动单位到目标格，按路径 `cost` 扣减燃料，标记为已行动。
2. 攻击方伤害结算，扣减防御方 HP，攻击方消耗 1 点弹药（若有）。
3. 防御方存活、双方相邻（曼哈顿距离 1）、防御方非间接火力、防御方有武器且弹药未耗尽时，**按扣血后的剩余 HP** 计算反击。
4. 反击扣减攻击方 HP，防御方消耗 1 点弹药（若有）。
5. 双方按「造伤 / 受伤」各自充能。
6. 移除 `hp ≤ 0` 的单位。
7. 若是占领指令，累加进度并判断归属变更；最后统一重置已失效的占领进度。
8. 检查胜负；若当前行动方在结算中出局，立即进入下一回合。

### 4.3 反击条件与伤害矩阵

被摧毁的单位不反击。间接火力既不反击也不被反击。

完整伤害数值见 `public/shared/engine.mjs` 的 `DAMAGE` 表；`test/contract.test.mjs` 用镜像表推导期望值，确保公式与数据不会同时被改错。

### 4.4 迷雾下的日志可见性

M4 起，攻击、生产、补给、埋伏与回合收入都会按迷雾规则分流（见 10.2）：涉及对手的情报只写进参战双方的私有条目，公共日志只保留不含金额与兵种的摘要。关闭迷雾时日志行为与 M3 完全一致。

## 五、占领

- 只有步兵与机动步兵（`capture: true`）可以占领。
- 只能占领中立或敌方建筑；盟友建筑、空地、非据点地形均不可占领。
- 每次占领扣除**当前可视 HP** 点进度；据点初始进度 20，扣至 0 完成占领。
- 满血步兵占领中立城市/工厂需 2 次，总部需 2 次（总部同样从 20 开始）。
- 进度与占领者绑定：同一席位续占保留进度，其他席位接手会重置为 20。
- 占领者离开、被消灭或换成非占领单位，进度重置为 20 且 `captureBy` 清空。
- 占领总部落成时，原持有者立即出局，总部转归占领方，进度重置为 20。

占领合法性由导出的 `canCapture(state, seat, unit, x, y)` 统一判定，服务端与客户端共用，不要在前端另写条件组合。

## 六、经济、维修与补给

- **收入**：每座己方据点（城市/工厂/总部）每回合 1000，于本方回合开始时发放。
- **维修**：本方回合开始时，站在己方或盟友据点上的本单位自动恢复，每回合最多 2 点，直到 10。
  - 每点费用 = 单位造价 ÷ 10（步兵 100，重型坦克 1600）。
  - 资金不足时按可用资金少修或不修，资金不会变负。
  - 维修不消耗「补给自己」的名额，与补给独立结算。
- **补给**：据点上的本单位免费补满弹药与燃料。补给车待机或执行补给时，为相邻友军补满弹药与燃料，该动作不收费。
- **生产**：只能在己方、空置且类型匹配的生产设施生产（工厂→地面、机场→空中、港口→舰船，见 11.1）。扣款后新单位立即出现在该格，`acted = true`，下一个己方回合才能行动。
- 单位上限：AI 会在己方单位数达到 24 时停止生产；规则层本身不对单位总数设限。

## 七、指挥官与能力

| 指挥官 | 被动 | 普通能力（50） | 超级能力（100） |
| :--- | :--- | :--- | :--- |
| 林岚（突击先锋） | 全军攻击 ×1.1 | 攻击 ×1.25，移动 +1 | 攻击 ×1.4，移动 +2 |
| 周衡（战地工程师） | 全军防御 ÷1.1 | 全军恢复 2 HP 并补满补给 | 恢复 4 HP、补满补给、防御 ÷1.3、移动 +1 |

移动加成同样作用于林岚以外的指挥官时只在超级能力提供 +1。

- 能力只能在**本方回合、尚未发动过**时使用，消耗对应能量（50 / 100）。
- 效果持续到**下一次本方回合开始**，期间跨过敌方回合。
- 能力生效期间**不再积累能量**；普通能力剩余量必然 ≤ 50，超级能力则清零。这项一致性由 `validateState` 强制。
- 弹药与燃料的补充不重置 `acted`。

能量充能：每次攻击或反击产生

$$
\Delta E = \max\left(2,\ \left\lceil \frac{\text{伤害} \times \text{受影响单位造价}}{1800} \right\rceil\right)
$$

攻击方与防御方按各自造伤/受伤分别结算，上限 100。

## 八、胜负与淘汰

- **出局条件**（任一满足）：总部被占领；或既不拥有单位也不拥有工厂。
- 出局时：清除其全部单位、建筑转为中立、能力状态清空。
- **胜利条件**：只剩一支队伍存活时对局结束，该队伍的 `team` 记为 `winner`。
- 2v2 采用单人淘汰制：一人出局不影响同队另一人继续作战；同队两人都出局时该队判负。
- 投降等同出局，随后正常检查胜负。
- 对局结束后，任何新的规则指令（含 `endTurn`）都会被拒绝。

## 九、指令协议

### 9.1 指令类型

```jsonc
{ "type": "move", "unitId": "u12", "x": 4, "y": 3, "command": "wait" }
// command 取值：wait | capture | attack | supply | load | unload | join
// command 为 attack 时另带 targetId
{ "type": "build", "unitType": "infantry", "x": 0, "y": 0 }
{ "type": "power", "level": "power" }   // level 取值：power | super
{ "type": "endTurn" }
{ "type": "surrender" }
```

攻击不是独立的顶层指令，而是 `move` 的 `command` 之一，携带 `targetId`。

### 9.2 校验矩阵

所有以下情况必须被拒绝，且**不改变输入状态**（已由测试逐项断言）：

| 类别 | 被拒绝的情形 |
| :--- | :--- |
| 身份 | 非当前回合席位、席位已战败、未知 `playerId`、令牌无效 |
| 结构 | 非对象、数组、`null`、缺少 `type`、未知 `type` |
| 移动 | 单位不存在或不属于该席位、单位已行动、目标格不可达、坐标越界或非整数、未知 `command` |
| 攻击 | 目标不在射程内、弹药为 0、间接火力移动后开火、目标是友军或盟友 |
| 占领 | 非步兵/机动步兵、目标非据点、目标是己方或盟友建筑 |
| 补给 | 非补给车执行补给 |
| 生产 | 兵种不存在、目标非己方工厂、工厂被占用、资金不足（含 `__proto__` 等原型链键） |
| 能力 | 非法 `level`、能量不足、本回合已发动 |
| 回合状态 | 对局已结束 |

服务端另有两层保护：`token` 必须属于该席位；`revision` 必须匹配，否则返回 409 而不改变状态。

### 9.3 幂等与重试（M2 已实现）

每个玩家决策携带一个客户端生成的 `requestId`（8–64 位 `[A-Za-z0-9_-]`），服务端按房间与席位去重：

| 情形 | 结果 |
| :--- | :--- |
| 新 `requestId`，指令合法 | 执行，记录 `requestId → {席位, 负载指纹, revision}`，返回新状态 |
| 相同 `requestId` + 相同负载 | **回放**：返回当前房间与 `replayed: true`，不重复执行 |
| 相同 `requestId` + 不同负载 | `409`，拒绝复用编号 |
| 相同 `requestId` + 不同席位 | `403`，编号不可跨席位 |
| 非法 `requestId` 格式 | `400`，在任何状态检查之前拒绝 |
| 未带 `requestId` | 退化为 `revision` 冲突检测 |

关键设计：

- **去重先于回合与版本检查**。已生效指令的重试必然在回合推进之后到达，若先查「是否轮到你」会误报。
- **只有成功执行的指令才记录**。被规则拒绝（资金不足、路径非法等）的请求保持可重试。
- 记录上限 **64 条**，超出后丢弃最旧的；历史记录不足时该次重试退化为普通 `revision` 冲突。
- 记录**随存档持久化**（存档版本 2），服务重启后重试仍能识别为回放。
- 记录**不下发给客户端**：`publicRoom` 不含该字段，广播与查询接口都不泄漏 `requestId`。
- `start` 与 `rematch` 会清空记录，避免上一局的编号在新对局中意外命中。

**已知限制**：记录上限为 64 条且按时间淘汰，长时间对局中的陈旧重试会被当作新请求。客户端应当只用 `requestId` 覆盖「网络层重试」这一种场景，不要把它当作持久化的操作日志。

### 9.4 重连与快照

- 席位令牌（`token`）随浏览器存储，刷新或断线后用 `/api/rooms/{id}?token=…` 恢复原席位。
- 建立 SSE 连接时服务端**立即推送完整快照**，客户端无需增量补齐；`revision` 用于丢弃过期推送。
- 断线期间的多步变更在重连时合并为一次最新快照。客户端应放弃中途动画，直接切到新状态。
- 同一席位可同时存在多条 SSE 连接（多标签页）；每条都会收到同样的变更。
- 服务端在关闭时先排空写入队列，再关闭连接，因此不会出现「已确认但未落盘」的窗口。

## 十、战争迷雾（M4 已实现）

迷雾是**房间级开关**（`room.fog`，开局写入 `state.fog`），开局后不可更改。默认关闭；关闭时 `projectState` 直接返回主状态本身，不复制。

### 10.1 视野与隐蔽

- 视野是**曼哈顿半径**，无视线遮挡：障碍物不会挡光，只藏人。半径按兵种固定：侦察车 5，轻型坦克 3，步兵／机动步兵／重型坦克 2，火炮／火箭炮／补给车 1。
- 某格可见 ⟺ 某个**友方（含队友）**单位的视野半径覆盖它。**队伍共享视野**：2v2 队友看到的是两边单位的并集，但各自只知道并集本身，不共享未看见的情报。
- **森林与山地会藏住站在里面的单位**：可见格上的敌军只有在没有己方单位与之相邻（曼哈顿距离 1）时才被隐藏。己方单位在任何地形上都对自己可见。
- 视野内但在隐蔽地形上的**格子本身依然可见**：迷雾藏的是部队，不是地图。地形与建筑归属对所有席位永久公开，因为它们是规划目标所必需的信息。

### 10.2 按席位投影

`projectState(state, seat)` 是客户端唯一被允许看到的状态，也是服务端唯一的出口。相对主状态：

| 内容 | 处理 |
| :--- | :--- |
| 单位 | 删除 `seesUnit` 判定为不可见的单位，**不留残影**（没有「上次已知位置」）。离开视野即刻消失 |
| 他方资金与能量 | `funds` / `energy` 置为 `null`（队友保留真实值） |
| 无视野格的占领进度 | `capture` 复位为 20、`captureBy` 置为 `null` |
| 日志 | 私有条目（`{ seat, message }`）只发给该席位（含队友），其余条目降为公开文本 |
| 地形与建筑归属 | **不做任何裁剪**，永久公开 |

投影是快照而不是增量，因此客户端不需要维护「已知但当前不可见」的独立缓存。投影结果**不是合法存档**（资金为 `null`、单位列表是子集），因此不得用 `validateState` 校验，也不得写回存档；`projectState` 必须幂等（对投影再次投影得到同一结果）。

### 10.3 埋伏

迷雾中客户端看不到隐蔽敌军，它画出的路线会把那些格子当成空地。服务端复算这条路线（`reachable(projectState(state, seat), …)`），一旦撞上真实存在的敌军：

1. 行军**截断在碰撞点之前**，而不是按主状态绕行到原目的地——否则玩家能从「怎么绕过去的」反推迷雾里有什么。
2. 落点回退到路径上最后一个**可停留**的格子（友军格可过路不可停留）；全被占满则原地不动。
3. 原指令（占领／攻击）**不再结算**，只结算移动本身，单位标记为已行动。
4. 日志写入私有条目「遭遇埋伏，行军被迫中止」。

### 10.4 边界

- **规则不因看不见而放水**。`reachable` 与 `attackable` 完全忽略迷雾；命中视野内隐蔽地形上的敌军仍然合法。迷雾只改变「谁看得见什么」，不改变任何合法性判定。
- 指挥官的 AI 在迷雾房间中**只读本队投影**（`chooseAIAction` 内部即投影），因此它不会对没侦察到的单位做出反应，也不会绕过玩家不可能知道的阻挡。
- 迷雾下的私有日志、收入金额与占地进度都属于「情报」而非「规则」；它们不进 `validateState` 的语义，只影响投影结果。

## 十一、海空军与运输（M5）

> 本节先于实现冻结。新增兵种、地形与指令都必须同时落到「数据、规则、AI、操作、表现、存档、测试」七处，缺一不算完成。

### 11.1 新地形

| 地形 | 防御★ | 收入 | 徒步 | 履带 | 轮胎 | 空中 | 舰船 | 可生产 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | :--- |
| 海洋 `sea` | 0 | — | ∞ | ∞ | ∞ | 1 | 1 | — |
| 机场 `airport` | 3 | 1000 | 1 | 1 | 1 | 1 | ∞ | 空中单位 |
| 港口 `port` | 3 | 1000 | 1 | 1 | 1 | 1 | 1 | 舰船单位 |

- 全部既有地形补上 `air: 1` 与 `naval: ∞`；河流 `water` 不是海，舰船不能进入。
- 机场与港口是可占领据点，归属、收入、占领规则与城市一致。
- 工厂只生产地面单位，机场只生产空中单位，港口只生产舰船单位；`build` 在类型不匹配时拒绝。

### 11.2 新兵种

| 兵种 | 造价 | 移动 | 射程 | 弹药 | 燃料 | 类型 | 类别 | 每回合耗油 | 特性 |
| :--- | ---: | ---: | :--- | ---: | ---: | :--- | :--- | ---: | :--- |
| 战斗机 `fighter` | 18000 | 9 | 1–1 | 9 | 40 | 空中 | 空中 | 2 | 只能攻击空中单位 |
| 轰炸机 `bomber` | 22000 | 7 | 1–1 | 9 | 45 | 空中 | 空中 | 2 | 不能攻击空中单位 |
| 运输直升机 `heli` | 6000 | 6 | 0–0 | ∞ | 40 | 空中 | 空中 | 2 | 载 1 个步兵/机动步兵 |
| 驱逐舰 `destroyer` | 18000 | 6 | 1–1 | 9 | 60 | 舰船 | 舰船 | 1 | 不能攻击空中单位 |
| 登陆舰 `lander` | 12000 | 6 | 0–0 | ∞ | 60 | 舰船 | 舰船 | 1 | 载 2 个地面单位 |

- 空中单位按 `air` 移动类型计价：**任何地形消耗 1**，可飞越单位、河流与海洋；但**只能停留在己方机场**（见 11.4 的续航理由），其他据点上空只能飞过。
- 舰船只能进入 `sea` 与 `port`；地面单位不能进入 `sea`，但可以进入 `port`。河流 `water` 不对舰船开放，因此河流地图只放城市、不放港口。
- 视野：战斗机 4、轰炸机 3、运输直升机 3、驱逐舰 4、登陆舰 2。
- 空中单位不会被森林或山地藏住（`isConcealable` 以 `movement !== "air"` 判定）。

### 11.3 目标类别与伤害

每个兵种声明 `class`（`ground` / `air` / `naval`）与 `targets`（可攻击的类别列表）。既有 8 种地面单位为 `ground`，`targets = ["ground", "naval"]`——它们打不到空中目标。战斗机 `targets = ["air"]`；轰炸机与驱逐舰 `targets = ["ground", "naval"]`；补给车、运输直升机、登陆舰没有武器。

伤害公式不变。`damage()` 在目标类别不在 `targets` 内时返回 0；`attackable()` 同样过滤。反击沿用「相邻、存活、非间接火力、有武器、弹药未耗尽、目标类别可攻击」六项条件。

### 11.4 每回合燃料消耗

- 空中单位在每个己方回合开始时消耗 2 点燃料，舰船消耗 1 点；地面单位不消耗。
- 顺序：重置 `acted` → 据点维修与补给 → 扣回合燃料 → 燃料归零的空中/舰船单位被摧毁（坠毁/沉没，写入日志）→ 补给车补给。
- **只有停在机场上的空中单位会补满燃料**；地面与舰船可在任意己方据点补给。否则一架停在占领来的城市上的飞机可以无限续航，永远无法被逐出。
- 停在己方据点上的飞行器会先补满再扣 2 点，因此「回机场」能续航；地面单位燃料归零不会自毁，只是无法移动。
- 货舱内的单位不消耗燃料，也不参与维修。

### 11.5 装载、卸载与合并

**装载 `load`**：`move` 指令的 `command`，`x,y` 指向相邻的友方运输单位。

- 运输单位必须相邻、容量未满、类型可载；步兵/机动步兵可上直升机；任意地面单位可上登陆舰。
- 装载不消耗燃料；装载单位标记已行动，位置跟随运输单位，并写入 `carriedBy`。
- 货舱单位不占棋盘格、不可被攻击、不提供视野、不参与占领与维修。

**卸载 `unload`**：`move` 指令的 `command`，`unitId` 为运输单位，`x,y` 为相邻落点。

- 落点必须能让**被载单位**合法停留（按该单位的移动类型判定），且当前没有单位。
- 运输单位标记已行动；**被卸载单位保留未行动状态**，本回合仍可移动或攻击。
- 一次卸载一个单位；多货舱运输可多次卸载。

**合并 `join`**：`move` 指令的 `command`，`x,y` 指向相邻的**同兵种**友军。

- 双方都不能携带货物；合并后保留原地不动的单位，移动来的单位被移除。
- 结果：`hp = min(10, 两者之和)`，弹药与燃料按各自上限相加后截断；移动方消耗行动。
- 合并不会返还资金。

**运输被摧毁**：货舱内单位一并被摧毁。玩家淘汰时同样销毁其全部单位，包括货舱。

**AI**：电脑会为自己生产的运输单位寻找乘客并装载，带载后朝「货物能落脚的最近敌方或中立据点」飞行/航行并卸载；同类残血单位相邻时会主动合并。这些指令与玩家指令走同一套 `applyAction` 校验，不存在特权路径。

### 11.6 状态不变量（新增）

- `cargo` 为 `null` 或单位 ID 数组；数组长度不超过该运输单位的容量，每个 ID 必须指向本局存在、同属该玩家、类型可载、且 `carriedBy` 指向该运输的单位。
- `carriedBy` 为 `null` 或一个存在且同属该玩家的运输单位 ID；被载单位的坐标必须等于运输单位的坐标。
- 货舱单位不计入棋盘占位检查；非货舱单位仍必须一格一个。
- 存活玩家至少拥有一支未被载的单位或一座生产建筑（工厂/机场/港口）；只有货舱单位、没有任何生产建筑的玩家仍会被淘汰。

- 客户端不再重复实现占领判定与间接火力判定，直接调用 `canCapture` / `attackable`。
- 动画跳过、页面失焦、减少动态效果不影响规则结果；服务端不等待动画完成。
- 客户端可用 `reachable` 做移动范围高亮与路径预览，但**最终合法性以服务端 `applyAction` 的结果为准**。

## 十二、修订流程

修改任一数值或规则时：

1. 同步更新 `public/shared/engine.mjs`。
2. 运行 `npm test`，确认 `contract.test.mjs` 与 `invariants.test.mjs` 的变化是预期的。
3. 更新本文对应章节。
4. 若涉及存档结构，提供迁移或明确拒绝旧版本，并在 `DEVELOPMENT-BASELINE.md` 记录。

只改实现不改本文，会让契约文档与实际行为脱节；只改本文不改实现，测试会失败。两边必须一起改。
