# M4 验收记录

> 验收日期：2026-10-16
> 对应路线：`参考技术路线.md` 的 M4「战争迷雾与策略 AI」
> 环境：Windows 10.0.19045 x64、Node.js v24.19.0、Chrome（CDP 驱动，1280×860）

验收分四条线：引擎规则、按席位下发的服务端行为、真实浏览器 GUI 流程、AI 不越权。

**路线验收原文**：「隐藏单位不会出现在对应客户端可读取的状态和事件中；视野变化、埋伏和重连结果一致；AI 无越权信息读取或无限决策循环。」

## 一、隐藏单位不出现在任何一条下发通道里

服务端只有一个出口函数 `publicRoom(room, seat)`，HTTP 快照、行动响应、SSE 广播全部走它。`test/fog-server.test.mjs` 覆盖了三条通道：

| 通道 | 检查 | 结果 |
| :--- | :--- | :--- |
| `GET /api/rooms/{id}?token=…` | 开局时每个席位只看到自己的单位；对手资金与能量为 `null` | 通过 |
| `POST /api/rooms/{id}/action` | 行动响应同样是本席位视图；生产记录只进自己的日志 | 通过 |
| `GET /api/rooms/{id}/events`（SSE） | 同一版本的两条连接各收到自己的投影；不含 `requestLog` 与 `token` | 通过 |
| 重连快照 | 与实时响应逐字段相同 | 通过 |
| 主状态 | 全程保留双方全部单位与真实资金，未被投影改动 | 通过 |

无迷雾房间的 `projectState` 直接返回主状态本身（不复制），因此老行为零开销、零差异，由 `test/fog.test.mjs` 的 `fog off keeps the shared projection identical to the master state` 锁定。

## 四、AI 不越权

- `chooseAIAction` 在迷雾房间中先 `projectState` 再决策。它在内存层面就无法读到未侦察的单位——投影里那些单位根本不存在。
- `test/ai-baseline.test.mjs` 保持全绿：AI 不产生非法指令、不空转、单次决策 < 250 ms、场面单位数 < 60。
- 代价可量化：同一张图 2 人对局，全图可见 264 步（第 21 天），迷雾下 429 步（第 29 天）。AI 在迷雾里会摸索前进，推进更慢——这是不越权的直接后果，不是缺陷。
- 未实现路线中的「按实测预算提供难度档位」，已记入 `DEVELOPMENT-BASELINE.md` 的 M4 遗留。
