## 三、AI

`chooseAIAction` 的扩展：

- **生产**：机场优先补战斗机（对方有空中单位时）或第一架轰炸机，再补一架运输直升机；港口在对方有舰船时优先驱逐舰，否则先造一艘登陆舰。陆地席位不会尝试造海空单位。
- **目标类别**：攻击候选来自 `attackable`，因此地面单位不会对空中目标产生无效指令，战斗机也不会被派去炸地面。
- **运输**：运输单位没有货物时把最近的己方乘客当作目标；带载后目标改为「货物能落脚的最近敌方或中立据点」，并在相邻合法落点发出 `unload`。
- **合并**：相邻同兵种且对方未满血时发出 `join`。
- 装载、卸载、合并都经过与玩家相同的 `applyAction` 校验，没有特权路径。

用 16 组完整对局（4 张图 × 2/3/4 人 FFA 与 4 人 2v2）实测：

| 指标 | 实测 |
| :--- | ---: |
| 全部对局在 6000 步内结束 | 16 / 16 |
| 最长一局步数 | 2360 步（training/4/ffa，第 77 天） |
| 装载指令 | 79 次 |
| 卸载指令 | 74 次 |
| 合并指令 | 113 次 |
| 空中单位攻击 | 372 次（fighter） / 138 次（bomber） |
| 舰船攻击 | 27 次（destroyer） |
| 单次决策最长耗时 | 2.0 ms（上限 250 ms） |
| 非法指令 / 非法状态 | 0 |

海空单位的生产在 16 局中合计 251 架飞行器、41 艘舰船；coast 图的 AI 会实际执行「登陆舰装载 → 渡海 → 卸载」，不再只造船不用船。

## 四、操作

`public/app.mjs`：

- 选中运输单位后，相邻友军格显示「装载上车」，相邻空格显示「卸载部队」，相邻同兵种友军显示「合并部队」。三者的合法性判定与 `applyAction` 共用一套条件（`transportOrderFor`）。
- 单位面板显示 `货舱 n/容量`，以及「燃料 40（−2/回合）」形式的每回合耗油提示。
- 建筑面板按类型区分：工厂→地面单位、机场→空中单位、港口→舰船单位；机场提示语写明「飞行器每回合耗油，只能在机场补满」。
- 选中海洋格时提示「海洋只有舰船与飞行器可以进入」。

## 八、本轮修复的两个问题

1. **河流地图的港口出不了船**。港口建在河岸，而契约规定舰船不能进入河流，实测四条港口造出的驱逐舰可达格数为 0，AI 却仍会为它们花钱。现在河流地图的四个临水点改为城市，只有 `coast` 保留四座港口；`seaTiles = 0` 的图不再生成港口。
2. **AI 造船不装货**。生产逻辑会造登陆舰与直升机，但决策循环从不发出 `load` / `unload` / `join`，运输单位全程空跑。补上相邻格评分后，16 局实测产生 79 次装载、74 次卸载、113 次合并。
